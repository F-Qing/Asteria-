# 题库导入解析：改造前后对比

> 一句话：**以前是"让 AI 把整份文件改写成标准格式的文本，再拿规则去猜"；
> 现在是"规则能认的直接认，认不出的让 AI 按固定格子（JSON）抽出来，程序逐题检查"。**

## 1. 你一共碰到了三个错误，它们不是一回事

| 现象 | 你看到的 | 真正的原因 |
|---|---|---|
| **A** | 页面上导入失败，提示「文件格式无法自动识别」 | 规则一条题都没切出来，而且这次请求没勾「AI 解析」 |
| **B** | 勾了「AI 解析」，还是失败 | AI 把文件"改写"得半好半残，残题混在结果里 |
| **C** | 日志里 `Field 'stem' doesn't have a default value` | 那条残题没有题干，程序把"空值"整列删掉不写，MySQL 直接拒绝 → **整批回滚** |

**A 和 B 是同一个病根的两条岔路，C 是它最后炸出来的地方。**
所以你会觉得"哪儿都不对"——其实是一条链子上的三个点。

## 2. 根因一：这份 Word 的写法，原来的规则不认识

| 这份文件实际长这样 | 原规则要求 | 结果 |
|---|---|---|
| 题号是 `（1）` `（2）`（全角括号） | 只认 `【第 1 题】` 和 `1.` / `1、` | 295 道题的题号**一个都不认** |
| 选项用**制表符**挤在同一段：`A．机器语言→B．汇编语言→C．高级语言` | 要求一个选项占一行 | 只认出 1 个选项，A 把 B/C/D 全吞进去 |
| 小节标题写成 `1．选择题` `2．简答题` | 行首是数字+点 = 题号 | 被当成题号，一整节题被吞进同一个块 |
| 章节写成 `习  题  1` | 只认 `【第 1 章】` 和 `第一章` | 章节全落到「默认章节」 |
| **全文没有任何答案** | 答案可有可无 | 245 道题答案只能是空的 |
| 题干紧跟在题号后：`（1）Python语言属于…` | 要求写 `题目：` 标签 | 题干提不出来（这条最致命） |

一句话：**这不是"文件格式不对"，是"规则覆盖不到"**。教材类 Word 基本都是这个写法。

---

## 3. 根因二：AI 那条路，让它干的是它最不擅长的活

改造前，AI 的任务是：**把整份原文逐字"改写"成标准格式的文本**，然后程序再拿规则解析一遍。

| 环节 | 会发生什么 | 为什么 |
|---|---|---|
| 你要它"逐字照抄 1 万字再插图标签" | 它做不到 100% | 模型没有"复制缓冲区"，是逐字重新生成；漏行、合并、改符号都是常态 |
| 你写"不得编造答案" | 它有时还是编 | 提示词是**建议**不是**强制**；而示例里每道题都带 `正确答案：A`，它会照着示例学 |
| 分块（每 6000 字一块） | 切点落在题目中间 | 实测 5 块里 **2 处**正好劈在选项 C/D 之间、Python 代码中间 |
| 每块单独处理 | 看不到全局 | "每章从 1 开始编号"这种规则它根本没法判断，编号必错 |
| `temperature=0.1`（想让输出稳定） | 在 DeepSeek 上**无效** | DeepSeek 的思考模式默认开着，官方文档写明：思考模式下 temperature 不生效 |
| 输出太长 | 可能被服务商砍掉半截 | `finish_reason=length`，而代码当时**没检查**这个 |

## 4. 根因三（最关键）：错了没人发现

改造前，整条链路上只有三道极松的关卡：

| 关卡 | 改造前它会检查什么 | 问题 |
|---|---|---|
| 第 1 关：给 AI 的要求 | 只是"请求"，不是"约束" | 模型遵守 90% 也算通过 |
| 第 2 关：AI 的返回 | 只检查**是不是空字符串** | 返回"抱歉我做不到"、返回半截、返回 markdown 代码块，全都算成功 |
| 第 3 关：解析结果 | 只检查**有没有一道题像样** | 295 道里只要 1 道正常就放行，其余残题长驱直入 |
| 第 4 关：入库 | 不检查题干是否为空 | 空题干 → MySQL 报错 → **整批回滚** |

**所以你的体感是"AI 也没用"，实际是"AI 干成了一半，剩下的一半把整批拖死了"。**

## 5. 改造清单（逐项对照）

### A. 规则解析（能不用 AI 就不用）

| 项目 | 改造前 | 改造后 | 涉及文件 |
|---|---|---|---|
| 题号识别 | `【第 N 题】`、`1.` | **增加 `（1）` 全角括号** | `QuestionParser.java` |
| 题干提取 | 必须有 `题目：` 标签 | **题号后面的文字直接当题干** | 同上 |
| 题型小节 | `1．选择题` 被当成题号 | 识别成"本节题型"，不再吞题 | 同上 |
| 章节 | `【第 N 章】`、`第一章` | **增加 `习  题  N`** | 同上 |
| Word 里的制表符 | 原样保留（选项挤成一行） | **当换行处理**，选项各自成行 | `DocxTextReader.java` |
| 空题干的残块 | 直接插库 → 报错回滚 | **跳过**，不影响同批其他题 | `BanksImportTransactional.java` |
| 失败提示 | 可能是空的（取到了空行） | 取第一行**非空**内容 | `BanksServiceImpl.java` |

### B. AI 兜底（从"整篇改写"改成"结构化抽取"）

| 项目 | 改造前 | 改造后 |
|---|---|---|
| AI 的任务 | 输出**标准格式的文本**，程序再用规则猜 | 输出 **JSON**：`{题干, 选项[], 答案, 题型, 章节}` |
| 格式靠什么保证 | 提示词的语气（软约束） | 接口参数 `response_format=json_object`（协议约束） |
| 题干 | 靠"有没有写 `题目：` 标签" | JSON 里 `stem` 字段，缺了立刻可见 |
| 编号 | 让 AI 排「第 N 题」 | **不让它编号**，顺序由分块顺序决定 |
| 编答案 | 只靠提示词"不许编" | 提示词禁止 **+** 程序校验：答案字母不在选项里就丢掉答案 |
| 选项 | 正则猜 | 逐项校验：字母非法/重复/内容为空就丢掉该项 |
| 没有题干的题 | 混进结果 → 入库报错 | **当场丢掉** |
| 分块 | 按字数切（劈在题目中间） | 按**题目边界**切（题号行/空行） |
| 出错 | 静默产出残题 | 每块重试 1 次；仍失败就报「**原文第 X~Y 行**」并整批失败 |
| 输出被截断 | 当成成功 | 检查 `finish_reason=length`，直接判失败 |
| DeepSeek 思考模式 | 默认开着（白烧钱、temperature 失效） | 只对 DeepSeek 的 V4 系模型发 `thinking: disabled` |
| 测试 | 没有 | 新增 9 个单测（`AiQuestionExtractorTest`）覆盖校验逻辑 |

**旧文件已被删除**：`ImportTextFormatter.java`（"让 AI 改写文本"的那一套），
新文件：`AiQuestionExtractor.java`。

## 6. 现在的完整流程

**改造前：**

```
上传文件
   │
   ├─ 规则解析 ──> 0 道题 ✗
   │
   └─ 勾了 AI？ ──> 让 AI 把整篇"改写"成标准文本
                      │  （劈题 / 编答案 / 漏标签 / 被截断，全都无法察觉）
                      └─> 再拿规则解析一遍 ──> 半好半残
                                │
                                └─> 只要有一道题像样就放行 ──> 残题插库
                                                                  │
                                                       MySQL 报错，整批回滚 ✗
```

**改造后：**

```
上传文件
   │
   ├─ 第一层：规则解析（毫秒级、0 成本、结果永远一样）
   │     └─ 认出题目 ──> 直接入库 ✓        ← 你的 295 道课后习题走这里
   │
   └─ 认不出？ ──> 第二层：AI 结构化抽取
                    ├─ 按【题目边界】切块（绝不劈题）
                    ├─ 要求模型输出 JSON（格式由接口保证）
                    ├─ 逐题校验：没题干→丢；选项非法→丢；答案不在选项里→丢答案
                    ├─ 不合格就重试；再不行就报「原文第 X~Y 行」
                    └─> 通过校验的题入库 ✓
```

## 7. 几个词，用人话解释

| 词 | 人话 |
|---|---|
| **规则解析 / 正则** | 提前写好"看到 `（1）` 就当新题开始"这类固定规则。快、免费、每次结果都一样，但只能认你想到的写法 |
| **软约束** | 你在提示词里写"必须…"，模型只是"倾向于"照做，没有任何机制强制它 |
| **结构化输出（JSON）** | 让模型把答案填进固定格子里（题干=…/选项=…/答案=…），格式由接口参数约束，而不是靠它自觉 |
| **校验** | 程序自己再检查一遍：题干不能空、答案字母必须在选项里。不合格的丢掉，不让它进数据库 |
| **截断** | 模型回答太长，被服务商从中间砍断（只给了一半） |
| **思考模式** | 模型先在"肚子里"推理一大段，再给答案。解数学题有用；"照抄+归类"这种活纯属浪费钱和时间 |
| **残题** | 被切了一半的题：只有选项没有题干，或题干没选项 |

## 8. 你现在需要知道的行为变化

1. **常见格式不再需要 AI**：教材式 Word、网页导出的 txt，规则直接吃，省钱省时间。
2. **AI 只在规则吃不下时出场**，而且只做"抽取"，不再"改写"——编答案这条路被提示词和校验双重堵住。
3. **失败会告诉你在哪失败**：报「原文第 X~Y 行」，而不是整批莫名其妙失败。
4. **题干为空的残块被跳过**，不会再出现"一条脏数据把整批回滚"。
5. **老题库文件导入结果不变**（已用你的样本回归验证）。
